# FC26 存档写入规则

FC26 `Squads` 文件是 `FBCHUNKS` 容器包裹的 `DB\x00\x08` 数据库。核心解析器沿用 FIFA 系列的位压缩表结构，但 FC26 的容器和数据库目录不同。

关键约束：

- 动态查找 `DB\x00\x08`，完整保留 DB 前的 FBCHUNKS 头。
- `DataSize` 位于文件偏移 14，保存时必须等于 `文件总长度 - 1126`。
- `DB` 头为 24 字节，表目录每项 8 字节；实际样本包含 83 张表。
- FC26 表头的 `field_count_raw` 写入字段数量本身，不加 `0x100`。
- 修改记录时只覆盖字段位，保留记录 padding、空槽、压缩字符串区和表尾元数据。
- CRC 使用 CRC-32/MPEG-2：多项式 `0x04C11DB7`、初值 `0xFFFFFFFF`、无最终异或。
- `SaveType_Squads\0` 后的 8 个旧哈希字节在数据库变更后归零。

编辑器的保存服务先写入临时文件，再重新解析并校验容器、表记录数量及每个修改字段，最后生成新的 `SquadsYYYYMMDDHHMMSS` 文件。原始存档不会被覆盖。

## 安全编辑范围

球员基础资料和能力值写入 `CZUM`；球衣号码、俱乐部/国家队关系使用现有 `RrqT` 记录原位修改。国家队选拔会复用目标国家队已有的 26 条 `RrqT` 关系记录，只替换球员 ID 和号码，不新增或删除记录。球队 `lyxL` 基础数据在 Web 编辑器中保持只读，以减少默认阵容和赛事数据被破坏的风险。

传奇球员和 `nQVU`（editedplayernames）姓名记录只能新增，不能删除既有球员。

## 生日字段的取值范围（重要）

`CZUM.birthdate` 是「1582-10-14 起算的天数」。**游戏会跳过生日越界的球员**：他在存档里存在，但不会出现在国家队选拔、转会等列表里。实测 FC26 自带数据里最老的球员是 `125812`（1927-04-01，普斯卡什），因此：

- 低于 `125812` 的值（例如 `legend_database.db` 里 Kempes 的 `130000`、Rivellino 的 `120000`）会让球员被游戏隐藏；Rivellino 的 `120000` 就是之前"加入成功却看不到"的原因。
- 旧版 ICON/英雄数据把生日写成「2007 年 + 真实月日」（例如 `155154` = 2007-08-01），导入后球员会显示成 18 岁。
- `155123` = 2007-07-01（18 岁），`155489` = 2008-07-01（17 岁），用于「全员 18 岁」快捷功能。

编辑器把这些规则集中在 `services/birthdates.py`：`REAL_BIRTHDAYS` 保存全部可导入传奇的真实生日，导入传奇时自动使用真实值；「全员 18 岁」会先把原始生日写入 `data/birthdate_snapshots/`，供「恢复原始生日」使用。
